# Orbit UI translations

Orbit supports the system language (with an English fallback), English,
Nederlands, Deutsch, Français, and Español. The selected preference lives in
the application's database setting `language`; the renderer applies that
preference after loading settings. The translator never persists a preference
by itself.

The local `src/ui/i18n.js` script loads before `controller-mode.js` and
`app.js`. No network access, third-party translation service, dynamic code
evaluation, or HTML translation strings are required.

## Renderer API

```js
window.OrbitI18n.t("Settings");
window.OrbitI18n.t("View details for {name}", { name: game.name });
window.OrbitI18n.setLanguage("nl");       // also accepts system, en, de, fr, es
window.OrbitI18n.getPreference();          // "system" or selected language
window.OrbitI18n.getLanguage();            // effective en/nl/de/fr/es
window.OrbitI18n.languages;                // {code, label, nativeName} entries
window.OrbitI18n.formatDate(new Date(), { dateStyle: "medium" });
window.OrbitI18n.formatNumber(1234.5);
```

Setting the language updates `document.documentElement.lang` and fires an
`orbit:languagechange` event with `detail.language` and `detail.preference`.
The system option follows the first entry in `navigator.languages` (falling
back to `navigator.language`). Unsupported system locales use English.
An explicit language choice is unaffected by system language changes.

Keys are **literal English source text**, including punctuation and spaces.
Unknown keys return the English source key unchanged. Interpolation replaces
only the supplied `{name}` placeholders, leaving missing parameters intact.
The English UI's pre-existing `Spelen` label is an intentional exception: it
is translated to `Play` when the effective language is English.

Update status labels from Electron (`src/core/updates.cjs`) and Tauri
(`src-tauri/src/lib.rs`) use a small catalog of known, exact backend messages.
The renderer translates them through `t(status.message)`. Unexpected backend
errors remain unchanged so diagnostics are not obscured by a broad text matcher.

## Safe rendering

`t()` returns ordinary, **unescaped text**. Use `textContent` to insert
translated strings into the DOM. When building `innerHTML` templates or
HTML attribute values, use the existing `esc()` / `escapeHtml()` renderer
helper **on the entire translated result**, including interpolated game names.
Do not insert translations using `innerHTML` without escaping, and do not
double-escape content already used with `textContent`.

```js
const label = window.OrbitI18n.t("View details for {name}", { name: game.name });
const safeAttribute = esc(label);
button.textContent = window.OrbitI18n.t("Play");
```

To extend translations, add a row to `entries` in `src/ui/i18n.js` in the
order: English, Dutch, German, French, Spanish. Keep the same placeholder names
in each language. Source keys from `app.js` and `controller-mode.js` are
verified for translation coverage by `tests/i18n.test.cjs`, which also rejects
duplicate English keys and mismatched placeholders.
